5. Why Next.js?
Recommendation: Next.js App Router
This isn't just because Next.js is popular.
The Digital Museum benefits from:
SEO
Project pages should be discoverable by search engines.
For example:
/museum/projects/quest-arena
should have its own:
title
description
Open Graph image
structured metadata
Server rendering
The textual content of project pages doesn't need to wait for WebGL to initialize.
Image optimization
Portfolio sites are image-heavy.
Routing
The museum naturally has multiple routes.
Backend capabilities
You don't need a separate Express/NestJS server for this product.
Next.js already supports full-stack application development. îˆ

6. Why TypeScript?
Strong recommendation.
You will eventually have objects like:
Project
Experiment
Artifact
Media
Exhibit
TimelineEntry
Without TypeScript, it's easy for fields to drift.
Example:
project.currentXP
versus:
project.xp
TypeScript catches these contract problems during development instead of letting them become UI bugs.
Next.js itself recommends TypeScript for type safety, and its documentation specifically notes the value of type-safe data structures. îˆ

7. Why Tailwind CSS?
Tailwind should handle the design system, not become the source of every visual decision.
Define tokens for:
colors
spacing
typography
shadows
borders
transitions
breakpoints
Example conceptual palette:
museum-black
museum-charcoal
museum-surface
museum-white
museum-muted
museum-gold
museum-gold-dim
museum-border
This is especially important because the museum needs a consistent visual language.

8. Animation Architecture
Use Motion for:
page transitions
modal transitions
exhibit hover
text reveals
navigation
UI interactions
Use Three.js/R3F for:
3D camera movement
lighting
particles
3D objects
museum architecture
Don't use Three.js for a simple opacity animation.
That's unnecessary complexity.

10. Three.js Performance Rules
This project can easily become a performance nightmare if you're not careful.
Rule 1
Don't create vectors/materials/geometries every frame.
Rule 2
Don't run unnecessary useFrame loops.
Rule 3
Reuse geometry and materials.
Rule 4
Dispose resources when dynamically created.
Rule 5
Lazy-load heavy 3D scenes.
Rule 6
Don't load every museum model on initial page load.
Rule 7
Use lower-poly models where possible.
Rule 8
Disable expensive effects on mobile.
Rule 9
Respect prefers-reduced-motion.
